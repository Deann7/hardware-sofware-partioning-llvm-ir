# LLVM IR-level fine-grained HW/SW partitioning for FPGA image kernels

Code, scripts and results for the paper *"Automated Fine-Grained Hardware/Software Partitioning at the LLVM IR
Level for FPGA Image Kernels: An Evaluation Against Manual, Monolithic, and Streaming HLS Baselines"*
(D. Saptono, D. N. A. Syahbanna, S. S. Nurhaliza).

An LLVM 18 pass (`hwsw-partition`) takes an unmodified C loop nest and does the following:

1. Finds the per-pixel output computation.
2. Extracts its backward data-flow slice.
3. Derives each window offset with scalar evolution.
4. Emits a straight-line Vitis HLS C++ kernel in two forms: per-window (AXI4-Lite) and line-buffer streaming (AXI4-Stream).
5. Rewrites the host IR to call the kernel.

Four kernels were run through csim, RTL cosim and Vivado place & route on a Zynq-7020 (xc7z020clg484-1) at 100 MHz:

- Sobel
- Gaussian 3×3
- Median 3×3
- Gaussian 5×5

Each kernel was implemented in six variants and compared against manual, monolithic and hand-written streaming baselines.

## Repository layout

| Path | Contents |
|---|---|
| `pass/` | `HwSwPartition.cpp`, the LLVM 18 new-PM pass, plus its CMake file |
| `kernels/<k>/ref.cpp` | Unmodified software reference (input to the pass) |
| `kernels/<k>/manual.cpp`, `stream.cpp`, `op.h` | Hand-written baselines: manual per-window and line-buffer streaming |
| `kernels/sobel/orig_hw.cpp` | Sobel kernel from the earlier manuscript |
| `kernels/<k>/gen/` | Pass output: `hw.cpp` (per-window kernel), `stream.cpp` (streaming kernel), `sw.ll` (rewritten host IR), `driver.inc`, `manifest.json`, intermediate IR |
| `common/` | HLS testbench (`tb.cpp`), full-image check (`verify.cpp`), streaming template (`stencil_stream.inc`) |
| `arm/` | Harness used to count Cortex-A9 instructions per image |
| `hls/run.tcl`, `run.bat`, `runall.bat` | Vitis HLS / Vivado flow for one design or for all designs |
| `hls/logs/` | Full Vitis HLS logs of every run |
| `hls/reports/` | Archived csynth, cosim and post-route (`export_impl.rpt`) reports of all 25 designs |
| `scripts/` | LLVM flow (`partition.sh`, `regen_all.sh`), ARM counts, result collection and figures |
| `results/` | `summary.csv` (all metrics), `e2e.csv` (time per image), `arm_count.csv`, `figs/` |

Kernels (`<k>`): `sobel`, `gauss`, `median`, `conv5`.

Variants:

| Variant | Description |
|---|---|
| `gen` | Generated by the pass, per-window |
| `gen_stream` | Generated by the pass, streaming |
| `manual` | Hand-written per-window |
| `stream` | Hand-written streaming |
| `mono` | Monolithic HLS: unmodified source, m_axi + s_axilite |
| `mono_pipe` | Same as `mono`, with the X loop pipelined |
| `orig` | Sobel only: kernel from the earlier manuscript |

## Main results (64×64 image, 100 MHz)

| Kernel | CPU-only, ARM -O3 (estimate) | `gen` per-window | `gen_stream` | Streaming vs CPU |
|---|---|---|---|---|
| Sobel | 258–515 µs | 3485 µs | 42.5 µs | 6.1–12.1× |
| Gaussian 3×3 | 188–377 µs | 3757 µs | 42.5 µs | 4.4–8.9× |
| Median 3×3 | 2031–4062 µs | 4372 µs | 42.5 µs | 48–96× |
| Gaussian 5×5 | 386–772 µs | 8758 µs | 43.8 µs | 8.8–17.6× |

All 25 designs are bit-exact in C simulation and RTL co-simulation and meet timing after place and route.
Area and Fmax for every design are in `results/summary.csv`.

The CPU column is an estimate, not a board measurement: dynamic ARM instruction count (from qemu) × CPI 1–2 at 667 MHz.
The FPGA times are cosim cycles at 100 MHz. For the per-window designs these are lower bounds, because the ARM-side
loop overhead is not included.

## Reproducing

Tools used:

- **WSL (Ubuntu):** `clang-18`, `opt-18`, `llvm-18-dev`, `g++-arm-linux-gnueabihf`, `qemu-user`
- **Windows:** Vitis HLS / Vivado 2023.2
- **Python:** 3 with `matplotlib`

The scripts use absolute paths: `D:/Ayah/Percobaan2` (Windows), `/mnt/d/Ayah/Percobaan2` (WSL) and `E:\Xilinx`.
If your locations differ, change `ROOT`/`root` in `scripts/*.sh`, `hls/run.tcl` and `hls/*.bat`.

```bash
# 1. Build the pass and run the LLVM flow for all kernels (WSL).
#    Each kernel prints "PASS: 0 mismatches over 8 images".
bash scripts/regen_all.sh
# 2. ARM instruction counts (WSL) -> results/arm_count.csv
bash scripts/arm_count.sh
```

```bat
rem 3. HLS + cosim + place & route (Windows).
rem    One design:
hls\run.bat sobel gen csim+csynth+cosim+impl
rem    All designs (one at a time, each P&R needs several GB of RAM):
hls\runall.bat
```

```bash
# 4. Tables and figures. Run from the repository root.
#    collect.py reads hls/prj when present, otherwise the archived hls/reports.
python scripts/collect.py
python scripts/e2e.py
python scripts/figs.py
```

Full Vitis projects (`hls/prj/`, about 1.3 GB) are not included. `hls/runall.bat` regenerates them.
